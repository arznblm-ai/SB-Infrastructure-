# Ранбук: групповой Марко на VPS

### [[2026-09-18]]

Бот живёт только на VPS (163.5.29.10). Деплой запускается с мака: `bash deploy.sh` из этой папки.

## 1. BotFather

В @BotFather:
- `/newbot` → имя и юзернейм → сохранить токен;
- `/setprivacy` → выбрать бота → **Disable** (иначе бот не видит сообщения в группе, кроме команд);
- `/setjoingroups` → **Enable**.

## 2. Группа

Создать группу, добавить Ралину и бота. Сделать бота **админом** с правом закреплять сообщения (закреп с планом бот редактирует сам).

## 3. Первый деплой

```bash
bash deploy.sh
```

Скрипт положит образец `.env` на сервер и остановится. Заполнить:

```bash
ssh -t -i ~/.ssh/id_ed25519_vps root@163.5.29.10 nano /root/.config/marco-group/.env
```

Вписать `TELEGRAM_BOT_TOKEN` и `BOT_USERNAME`. `GROUP_CHAT_ID` **оставить пустым** — это режим настройки.

## 4. Второй деплой и сбор id

```bash
bash deploy.sh
```

Написать что-нибудь в группе — от Антона и от Ралины. На каждое сообщение бот ответит `chat_id` и `user_id` автора. Вписать в `.env`: `GROUP_CHAT_ID`, `USER_ANTON_ID`, `USER_RALINA_ID`. Затем:

```bash
ssh -i ~/.ssh/id_ed25519_vps root@163.5.29.10 systemctl restart marco-group
```

## 5. Smoke-тесты

1. Тег бота с вопросом (`@<bot> что по завтрашнему дню?`) — должен ответить по плану.
2. Кинуть ссылку на инстаграм-рилс. Проверка yt-dlp с IP VPS: если метаданные не приходят, бот спросит название места — **это ожидаемый фолбэк**, не баг.
3. `/status` — бот отвечает состоянием.
4. `/plan` — бот отдаёт текущий план.
5. WebSearch в headless: спросить погоду на завтра в точке маршрута. Ответ с актуальными цифрами = поиск работает.

## 6. Диагностика

```bash
ssh -i ~/.ssh/id_ed25519_vps root@163.5.29.10
systemctl --no-pager status marco-group
journalctl -u marco-group -f
tail -f /root/.config/marco-group/bot.log
```

## 7. Грабли

- **Privacy mode.** Не выключил в BotFather — бот молчит на всё, кроме команд. Лечится в BotFather + рестарт бота.
- **Один токен = один процесс.** Если бот запущен ещё где-то (мак, старый юнит), Telegram будет рвать long polling у обоих. Держать только VPS-процесс.
- **Перезапуск изнутри.** Нельзя `systemctl restart marco-group` из сессии, живущей внутри этого же юнита — убьёшь себя. Только отложенно: `systemd-run --on-active=30 systemctl restart marco-group`.
- **Квота Claude общая** с Крис и AI Twitter Digest, модель — Opus. Болтливая группа = заметный расход; при просадке квоты смотреть, не зациклился ли бот на прогонах.
- **Состояние процесса не синкается.** `state.json` и `bot.log` лежат в `/root/.config/marco-group/` и на мак не приезжают — бот существует только на VPS. Синкается через Syncthing только `group/` (план, закреп, сегменты, напоминания, чатлог).
