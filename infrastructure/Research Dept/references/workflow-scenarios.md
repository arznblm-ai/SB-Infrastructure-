# Workflow Scenarios

## 1. Market Intelligence

Use when:

- the user wants maximum relevant public market information;
- the run is not explicitly interview-led or corpus-shifted.

Required outputs:

- Market Intelligence Dossier
- CEO Market Intelligence Report
- HTML export of the CEO report
- optional factual packet
- registry update

## 2. Objective Market Scan

Use when:

- the user wants a neutral category map or space overview.

Required outputs:

- Neutral Market Dossier
- CEO Market Scan Report
- HTML export of the CEO report
- optional factual packet
- registry update

## 3. Interview-Led Market Overview

Use when:

- the user asks for interviews, podcasts, founder/operator voices, conference talks, public conversations, or practitioner commentary to drive the report.

Required outputs:

- Corpus Plan
- Voice Map
- Interview-Led Dossier
- CEO Interview-Led Report
- HTML export of the CEO report
- optional factual packet
- registry update

## 4. Competitive Messaging Intelligence

Use when:

- the user asks how competitors advertise, sell, position, frame pain, present offers, write CTAs, or structure landing-page/product-page messaging;
- the output should explain observed public messaging patterns, not recommend a campaign.

Required outputs:

- Messaging Corpus Plan
- Ad/Landing/Social Source Inventory
- Competitive Message Map
- Competitive Messaging Dossier
- CEO Messaging Intelligence Report
- HTML export of the CEO report
- optional factual packet
- registry update

## 5. Account / ICP Intelligence

Use when:

- the user asks for ICP, leads, buyer personas, target accounts, prospect/account qualification, or a factual map of public fit signals.

Required outputs:

- ICP Hypothesis
- Public Account Source Inventory
- Account / ICP Map
- ICP Intelligence Dossier
- CEO ICP Intelligence Report
- HTML export of the CEO report
- optional factual packet
- registry update

## 6. Corpus-Shift Rerun

Use when:

- topic already exists;
- user wants a new run through a different evidence corpus;
- old canon should not remain default backbone.

Required outputs:

- Prior Canon Review
- Corpus Shift Plan
- New corpus-driven dossier
- CEO report built from new corpus
- HTML export of the CEO report
- registry update with corpus metadata

## 7. Verification

Use when:

- the claim is narrow and the output is a verdict.

Required outputs:

- Verification Memo
- optional CEO Verification Note
- optional HTML export if a CEO-readable note is produced
- registry update when canon-worthy
