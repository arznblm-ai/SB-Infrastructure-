# Route — кем исполнять

### [[2026-08-10]]

Этот скилл не конвейер. Стадии (план → архитектура → execution → verify) живут в `model-pipeline/SKILL.md`. Route отвечает на один вопрос: **кто исполняет прямо сейчас и как его вызвать.**

Принцип: протокол формулируется в терминах **способностей**, а не имён инструментов. Имя конкретного CLI, модели или подписки появляется ровно в одном месте — в реестре ниже. Смена инструментария = правка реестра, а не переписывание скиллов.

Механизм, ради которого это сделано: документ протухает молча, проверка — нет. Прежняя версия этого файла на 147 строк была целиком построена на одном исполнителе и полгода утверждала его наличие прозой; статус исполнителя теперь не хранится в тексте, он **определяется health-check в момент вызова**.

## Контракт исполнителя

Исполнитель — любой агент, субагент или CLI, который умеет всё из списка:

1. **Пишет только в каталоге задачи.** Корень vault, чужие проекты, домашний каталог — вне досягаемости.
2. **Выполняет команды в этом же каталоге** (тесты, запуск, smoke-check).
3. **Принимает точечную спецификацию** и не требует «разберись в проекте».
4. **Возвращает краткий отчёт**: что изменил, список файлов, как проверил, риски и допущения. Отчёт — материал ревью; полный diff главная сессия не читает.
5. **Короткоживущий**: одна задача + не более 2 ревью-итераций, дальше свежий вызов с компактной спецификацией состояния.
6. **Имеет проверяемую живость** — одна команда, отвечающая «доступен / нет», без гадания.
7. **Известна квота**, из которой он тратит.

Не выполняет пункты 1, 4, 5 — это не исполнитель, и задача ему не отдаётся.

## Спецификация задачи (одинакова для всех исполнителей)

Это и есть переносимость: смена исполнителя — смена адресата, а не переписывание задачи.

- **строка требований** — одной строкой перед выбором и повторяется в отчёте: `требуется: файлы, команды, сеть?, изоляция?, квота≠сессии?`. Она делает маршрут аудируемым: видно, почему выбран именно этот исполнитель;
- цель и expected output;
- **точные пути файлов**, а не описание проекта;
- релевантный кусок `## Architecture` из план-файла;
- запреты: чего не трогать, никаких `git commit/push`, никаких внешних отправок, никаких миграций;
- требуемый формат ответа — краткий отчёт по пункту 4 контракта.

## Реестр исполнителей

Единственное место в vault, где названы конкретные инструменты. Порядок строк = порядок выбора по умолчанию.

| id | Вызов | Health-check | Способности | Квота |
|---|---|---|---|---|
| `claude-subagent` | `Agent` с `model: opus` (execution) или `model: sonnet` (чтение-дайджесты, план, обновление карты) | доступен всегда внутри сессии | файлы, команды, сеть — инструментами сессии | **та же, что у главной сессии** |
| `codex-cli` | `$CODEX exec` / `exec resume` (шаблоны в «Адаптерах») | `test -x /Applications/ChatGPT.app/Contents/Resources/codex` && `$CODEX --version` | файлы, команды; сеть и изоляция — **только если флаг передан в вызове** | подписка ChatGPT — **занята рантаймом ботов** |

**Квота ChatGPT — не свободный ресурс (решение Антона, 2026-08-10).** Через тот же Codex OAuth работают мозги живых ботов: Гермес и Алина. Разработка на этой подписке конкурирует с ними за их собственный рантайм, поэтому `codex-cli` для execution **не берётся по умолчанию**, даже когда health-check зелёный. Дефолт — `claude-subagent`. Исключение только одно: прямой форс Антона («через джипити») в конкретной задаче.

Появился третий инструмент — строка добавляется сюда, и больше никуда.

**Колонка «Способности» описывает потолок, а не гарантию.** Изоляция и сеть у CLI-исполнителей задаются флагами конкретного вызова, а не природой инструмента: глобальный конфиг Codex стоит в `danger-full-access`, и без явного `--sandbox workspace-write` песочницы нет, сколько бы ни было написано в этой таблице. Требуется изоляция — она обеспечивается флагом в вызове и проверяется в отчёте исполнителя, а не выбором строки реестра.

**Квота — главный критерий выбора, а не сноска.** Смысл внешнего исполнителя в том, что расход уходит **не из квоты главной сессии**. Если требование задачи включает «не тратить квоту сессии», строка `claude-subagent` его не удовлетворяет по определению — и это единственный случай, когда дефолт обязан уступить.

**Статус исполнителя не описывается прозой.** Никаких «⏸ временный режим, инструмент недоступен» в теле скиллов: такая строка живёт дольше, чем факт, который её породил. Расхождение документа и health-check решается в пользу проверки.

## Правило выбора

1. **Явный форс Антона** исполняется без раздумий: «через джипити» → `codex-cli`; «на клоде», «на опусе» → `claude-subagent`. Health-check всё равно выполняется — форс не отменяет проверку, он задаёт первого кандидата.
2. **Без форса** — требования задачи сверяются с реестром: нужна ли сеть, нужна ли изоляция, какая квота сейчас дешевле. Берётся первый исполнитель, который проходит health-check и покрывает требования.
3. **Health-check провален** — берётся следующий по реестру, и Антону **говорится вслух**, кем исполняем и почему не тем, кого он ждал. Молча подменять исполнителя запрещено.
4. **Исполнитель называется в отчёте** каждый раз. «Сделано» без имени исполнителя — неполный отчёт.
5. Ни один исполнитель не проходит — стоп и вопрос Антону. Не изобретать обходные пути.

**Дефолт по умолчанию — первая строка реестра** (`claude-subagent`). Смена дефолта на `codex-cli` — решение Антона, оформляется перестановкой строк реестра и ADR-записью, а не правкой протокола.

## Адаптеры

Грабли конкретных инструментов. Читаются только при выборе этого исполнителя.

**`codex-cli`** (проверено 2026-07-13, бинарь v0.147 жив на 2026-08-09):

```bash
CODEX=/Applications/ChatGPT.app/Contents/Resources/codex
"$CODEX" exec --skip-git-repo-check --sandbox workspace-write \
  -C "<корень проекта>" -c model_reasoning_effort="medium" \
  "<спецификация>" </dev/null
# итерация с сохранением контекста:
"$CODEX" exec --skip-git-repo-check --sandbox workspace-write -C "<корень>" \
  resume --last "<замечания ревью>" </dev/null
```

- `</dev/null` обязателен: без него процесс висит, ожидая закрытия stdin;
- флаги строго **до** субкоманды `resume`, иначе `unexpected argument`;
- `--sandbox workspace-write` обязателен — глобальный конфиг стоит в `danger-full-access`, флаг его переопределяет; `read-only` для чтения-дайджестов;
- reasoning effort задавать per-call (`medium` — execution, `low` — чтение): глобальное значение в `~/.codex/config.toml` плавает;
- сеть — `-c sandbox_workspace_write.network_access=true`; нативного веб-поиска нет, discovery через `curl` (DuckDuckGo lite с браузерным User-Agent, Google News RSS);
- таймаут Bash-вызова 300–600 сек; расход и остаток квоты — в конце вывода и в `rate_limits` свежего `~/.codex/sessions/**/rollout-*.jsonl`.

**`claude-subagent`**: вызывается инструментом `Agent` с явным `model`; марафон через `SendMessage` запрещён (кейс 03.08 — 870 сообщений, ~305 млн cache-read токенов); следующая порция работы — новый субагент с компактной спецификацией состояния.

## Что исполнителю не отдаётся

- `.md`-заметки vault — это текст, работа главной сессии или Sonnet-субагента;
- задачи с пометкой `human` из план-файла;
- `git commit/push`, миграции БД, удаление файлов, любые внешние отправки — только с явного подтверждения Антона, и в спецификации это пишется запретом;
- корень vault как рабочий каталог — никогда.

## Границы

- Стадии, план-файл, `ARCHITECTURE.md`, token discipline — `model-pipeline/SKILL.md`.
- Правки ≤5 строк в одном существующем файле — напрямую, без исполнителя.
- Архитектурное решение «как это устроить» — `/matt`, до выбора исполнителя.
- Допрос перед большой задачей без плана — `/grill`.
