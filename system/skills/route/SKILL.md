# Route — Fable мозг, GPT руки

Источник паттерна: reel cooper.simson (2026-07-11) — заметка в `transcripts/external resources/`.
Кросс-провайдерный вариант конвейера `model-pipeline`: те же стадии и token discipline, но **execution выполняет GPT 5.6 через Codex CLI** (headless), а не Opus-субагенты. Код пишется на квоте ChatGPT-подписки — лимиты Claude тратятся только на мышление.

## Принцип

**Fable (главная сессия) — мозг:** интервьюирует Антона, утверждает план, принимает архитектурные решения, ревьюит диффы, гоняет итерации.
**GPT 5.6 (Codex CLI) — руки:** получает точечную спецификацию + кусок архитектуры и пишет код. Возвращает diff и отчёт.

Мозг НЕ читает кодовую базу и НЕ пишет код. Руки НЕ принимают архитектурных решений.

## Инфраструктура Codex CLI (проверено 2026-07-11)

- Бинарник: `/Applications/ChatGPT.app/Contents/Resources/codex` (в PATH его нет; ставится вместе с ChatGPT.app, версия на момент проверки 0.144.0-alpha.4)
- Авторизация: ChatGPT-аккаунт Антона, токен `~/.codex/auth.json`, обновляется автоматически. При ошибке auth — сказать Антону залогиниться в ChatGPT.app, не выдумывать ключи
- Модель: берётся из `~/.codex/config.toml` (`model = "gpt-5.6-sol"`) — флаг `-m` не нужен, пока Антон не попросит другую
- Reasoning effort в config.toml стоит `low` — для кодинга поднимать до `medium` флагом (см. шаблон)

### Шаблон вызова (execution-задача)

```bash
CODEX=/Applications/ChatGPT.app/Contents/Resources/codex
"$CODEX" exec --skip-git-repo-check --sandbox workspace-write \
  -C "<корень проекта>" \
  -c model_reasoning_effort="medium" \
  "<спецификация задачи>" </dev/null
```

### Шаблон итерации (правки после ревью — контекст сессии сохраняется)

```bash
"$CODEX" exec resume --last --sandbox workspace-write -C "<корень проекта>" "<замечания по ревью>" </dev/null
```

- **`</dev/null` обязателен** (проверено 2026-07-11): если stdin — открытая труба (фоновый запуск, пайп), Codex бесконечно ждёт её закрытия и висит, не начав работу. Признак: процесс живёт десятки минут, сессионный rollout-файл не создан
- `--sandbox workspace-write` обязателен: глобальный config.toml стоит в `danger-full-access`, флаг его переопределяет. Codex пишет только внутри `-C`-каталога
- Нужен интернет (чтение источников, скачивание ассетов) → добавить `-c sandbox_workspace_write.network_access=true` (проверено: curl из песочницы работает)
- `--skip-git-repo-check` нужен вне git-репозитория; внутри git-проекта безвреден
- Codex сам печатает diff и расход токенов в конце — это и есть материал для ревью
- Таймаут Bash-вызова ставить 300–600 сек: крупные задачи Codex делает минутами

## Workflow

### Стадия 0 — Подхват готового плана
Как в `model-pipeline`: проверь `tasks/<проект>/` на свежий план-файл `{*} {plan} <фича> – YYYY-MM-DD.md`. Есть — сразу Стадия 2.

### Стадия 1 — Интервью и план (мозг + дешёвый копатель)
1. Fable задаёт Антону 3–5 точечных вопросов (Context Confidence Gate), только если без них план будет неверным.
2. Раскопки контекста — **Sonnet-субагент** (`Agent`, `model: sonnet`): бриф + путь к проекту + `ARCHITECTURE.md` → план-файл в `tasks/<проект>/` (цель, задачи с зависимостями, пометки `human`/`agent`, out of scope).
3. Fable план проверяет на здравость, не пересобирает.

### Стадия 2 — Архитектура (мозг)
1. Fable читает **только** план-файл + `ARCHITECTURE.md` корня проекта. Нет карты — сгенерировать Sonnet-субагентом (контракт в `model-pipeline/SKILL.md`).
2. Дописать секцию `## Architecture` в план-файл: какие файлы менять, интерфейсы/контракты, порядок задач, что параллелится.

### Стадия 3 — Execution (руки: GPT 5.6)
1. На каждую задачу плана — один вызов `codex exec` по шаблону выше. В спецификацию:
   - цель задачи и expected output;
   - **точные пути файлов** (не «разберись в проекте»);
   - релевантный кусок `## Architecture`;
   - ограничения: чего не трогать, никаких git commit/push, никаких внешних отправок;
   - формат ответа — **обязательный краткий отчёт**: что изменил, список файлов, как проверил (тесты/запуск), какие риски и допущения.
2. Зависимые задачи — последовательно через `exec resume --last` (одна сессия Codex держит контекст). Независимые по разным файлам — можно отдельными `exec`-сессиями.
3. Fable ревьюит **отчёт Codex, не diff**. Полный diff читать только точечно: файлы, где отчёт указывает на риск, или где упали тесты. Читать diff целиком «чтобы убедиться» — запрещено (это и есть утечка токенов, ради которой конвейер существует).
4. Замечания → `exec resume --last "<фиксы>"`. **Лимит — 2 ревью-итерации.** Не сошлось после двух — короткий отчёт Антону с вариантами (принять как есть / переформулировать спеку / fallback Opus), не бесконечная петля.

### Стадия 4 — Verify и закрытие
1. Тесты/запуск/smoke-check — вторым `codex exec` / `exec resume` («прогони тесты, покажи вывод»), не локальным Bash в главной сессии. Fable читает только вердикт: pass/fail + короткий хвост лога. Локальный Bash — лишь когда Codex недоступен или нужен MCP/окружение вне песочницы.
2. Обновить статусы в план-файле; при структурных изменениях — `ARCHITECTURE.md` (Sonnet-субагент).
3. Отчёт Антону: что сделано, как проверено, сколько токенов съел Codex (из его вывода), что осталось на `human`.

## Контент-deliverables: HTML-презы и research-отчёты (2026-07-11)

Основной пожиратель лимитов Claude у Антона — не код-проекты, а **написание длинных HTML-файлов** (презентации для партнёров, research-отчёты): тысячи строк output-токенов топ-моделью. Это механическая работа рук — уходит GPT.

**HTML-презентации (design department):**
- Мозг (Fable): brief по `design department/references/brief-template.md`, нарратив, послайдовая структура, design direction (Portal brand bible) — компактная спецификация, не HTML.
- Руки (GPT): пишет полный HTML-файл по спецификации в рабочий каталог задачи (`tasks/<задача>/`). Итерации — `exec resume --last`.
- Ревью (Fable): открыть HTML в браузере, скриншот, критика по `quality-gates.md` (роль critic) → замечания списком в `exec resume`. **HTML-файл целиком не читать** — только скриншот + точечные `grep`/фрагменты по конкретным замечаниям. Fable файл не переписывает — только диффы замечаний. Лимит итераций тот же — 2, дальше отчёт Антону.
- Роли department: art-director и critic = мозг, generator = GPT. Orchestrator/brief — как раньше (Sonnet).

**Research-отчёты (Research Dept):**
- Мозг (Fable): research brief, source plan, верификация ключевых фактов, синтез выводов.
- Руки (GPT, с `network_access=true`): чтение источников по списку URL (curl + извлечение фактов в structured notes), затем — сборка финального HTML-отчёта по готовому синтезу.
- Дешёвая альтернатива чтению источников — Sonnet/Haiku-субагенты; выбирать по тому, какая квота свободнее (Claude vs ChatGPT 5h-окно).
- Fable никогда не пишет HTML-отчёт сам — только контент-скелет (выводы, факты, структура) для GPT.

**Контроль квоты GPT:** план Plus, 5-часовое окно скромное. После каждого прогона читать снапшот `rate_limits` из свежего `~/.codex/sessions/**/rollout-*.jsonl` и включать остаток в отчёт. Квота выбита → fallback Opus + сказать Антону.

## Route vs Pipeline — что выбирать

**С 2026-07-11 GPT-исполнитель — default для всех implementation-задач**: конвейер `model-pipeline` на стадии Execution вызывает Codex по шаблонам этого файла автоматически. Полное правило выбора исполнителя (когда fallback на Opus) — секция «Выбор исполнителя» в `model-pipeline/SKILL.md`.

| Ситуация | Что происходит |
|----------|----------------|
| Любая implementation-задача | `/pipeline` (или авто-роутинг) → execution через GPT 5.6 по умолчанию |
| «Через джипити», «route» | форс GPT-исполнителя без раздумий |
| «На опусе», «без джипити», Codex недоступен, правки .md-заметок vault | Opus-субагенты (fallback; полные критерии — «Выбор исполнителя» в `model-pipeline/SKILL.md`) |
| Debug-сессия: диагноз поставлен, нужен фикс кода >5 строк | диагностика — Claude, фикс — `codex exec` |
| Правка ≤5 строк в одном файле (typo, path, константа, флаг) | напрямую, без конвейеров |

## Token discipline и safety

- Все правила `model-pipeline` действуют: мозг не сканирует кодовую базу, спецификации точечные, планы переиспользуются между сессиями.
- Codex работает только внутри каталога проекта (`-C` + `workspace-write`). Никогда не давать ему `danger-full-access` и корень vault.
- Git commit/push, миграции БД, удаление файлов, внешние отправки — только с явного подтверждения Антона; Codex'у в спецификации это явно запрещать.
- `human`-задачи из плана не отдавать ни Codex'у, ни субагентам.
- Если Codex вернул ошибку авторизации или бинарник пропал (обновление ChatGPT.app) — сообщить Антону, не изобретать обходные пути.

## Пилот

Первый прогон — на реальной фиче в код-проекте (кандидат: `projects/Spot Films/`, карта есть). После прогона записать в план-файл: расход токенов Codex, число итераций ревью, впечатление о качестве кода GPT 5.6 против Opus-исполнителей.
