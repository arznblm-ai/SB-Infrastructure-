# EVAL — model-pipeline

> **Thesis:** Eval на роутинг и качество планирования скилла `model-pipeline`: 5 кейсов проверяют, что конвейер Sonnet → Fable → Opus разворачивается только на настоящих implementation-интентах, план ложится в `tasks/<проект>/` с проверяемыми задачами, а главная модель не читает кодовую базу целиком.

**Скилл:** `/Users/anton/AI AGENT FOLDER/Second Brain/system/skills/model-pipeline/SKILL.md`
**Формат:** роутинг-eval без фикстур. Каждый кейс — промпт в свежей сессии; оценивается решение агента (запускать конвейер или нет) и качество артефактов. Для кейсов TC-3/TC-5 можно останавливать прогон после Стадии 1–2 («покажи план, execution не запускай»), чтобы не жечь токены на реальный execution.

⚠️ Прогоны, создающие план-файлы, вести на тестовом проекте (например, временная папка `tasks/eval-model-pipeline/`), либо явно помечать план-файл как eval и убирать в `archive/` после прогона.

## TC-1 — Тривиальная правка → конвейер НЕ запускается

**Промпт:**
```
Поправь опечатку в README проекта Spot Films: «анлиз» → «анализ».
```

**Ожидание:** прямая правка (Edit одного файла), конвейер не разворачивается.

**Pass/fail:**
- [ ] PASS: агент делает правку напрямую, без Sonnet-плана, без план-файла, без Opus-субагентов.
- [ ] Нет создания файлов в `tasks/`.
- [ ] Нет чтения кодовой базы целиком — только целевой README.
- [ ] Правка выполнена корректно (или агент честно сообщил, что опечатка не найдена, — тоже PASS).
- FAIL, если: запущен любой субагент конвейера; создан план-файл; агент начал «Стадию 0/1» по SKILL.md.

## TC-2 — Однопредложенческий diff → тоже bypass

**Промпт:**
```
В Spot Films webapp добавь в footer строку с версией приложения из package.json. Это одна маленькая правка.
```

**Ожидание:** правка напрямую — по правилу «если задача тривиальна, конвейер не разворачивать: дешевле одного субагента» (Token discipline).

**Pass/fail:**
- [ ] PASS: без конвейера — прямая правка 1–2 файлов.
- [ ] Допустимо: агент заглянул в `ARCHITECTURE.md`, чтобы найти файл footer, — это соответствует правилу «сначала карта».
- [ ] Нет план-файла в `tasks/`, нет Sonnet/Opus-субагентов конвейера.
- [ ] Агент не сканирует проект широко (не более пары точечных файлов).
- FAIL, если: развёрнуты стадии конвейера; создан план-файл; агент прочитал десятки файлов ради однострочника.

## TC-3 — Полноценная фича → конвейер запускается, план валидный

**Промпт:**
```
Сделай в Spot Films webapp фичу: страница сравнения двух фильмов бок о бок —
выбор двух фильмов, таблица метрик, общий вердикт. Model pipeline.
```

*(Для экономии токенов допустимо добавить: «останови прогон после того, как план-файл готов и секция Architecture дописана; execution не запускай».)*

**Ожидание:** конвейер запускается: Стадия 0 (поиск готового плана) → Стадия 1 (Sonnet-план) → Стадия 2 (архитектура главной моделью).

**Pass/fail:**
- [ ] PASS-обязательно: агент опознал implementation-intent и пошёл по конвейеру (не стал писать код сам сразу).
- [ ] Стадия 0: агент проверил `tasks/<проект>/` и корень проекта на существующий план-файл до создания нового.
- [ ] План докапывает **Sonnet-субагент** (`model: sonnet`), а не главная сессия.
- [ ] План-файл создан в `tasks/<проект>/` по конвенции: `{*} {plan} <фича> – YYYY-MM-DD.md`, EN DASH перед датой, ≤ 80 символов.
- [ ] План содержит: цель и expected output; задачи списком с зависимостями; у каждой задачи пометка `human`/`agent`; секцию out of scope.
- [ ] Задачи проверяемые: у каждой понятен критерий «сделано» (что должно существовать/работать), а не «улучшить UX».
- [ ] Стадия 2: главная модель читает только план-файл + `ARCHITECTURE.md` и дописывает секцию `## Architecture` (файлы, контракты, порядок, параллелизм).
- [ ] Главная сессия НЕ сканирует кодовую базу и НЕ пишет код руками.
- [ ] Если прогон дошёл до execution: задачи исполняют Opus-субагенты с точными путями, независимые — параллельно.
- FAIL, если: главная модель сама читает кодовую базу целиком; план без пометок human/agent или без out of scope; план-файл не в `tasks/<проект>/`; код пишется без плана.

## TC-4 — Eval/review intent → конвейер НЕ запускается

**Промпт:**
```
Проверь, почему в Spot Films webapp не работает страница анализа фильма — вчера отдавала 500.
```

**Ожидание:** это review/debug-intent, не implementation. По SKILL.md («НЕ включаться: review/eval») и Router Rules конвейер не разворачивается — агент диагностирует.

**Pass/fail:**
- [ ] PASS: конвейер не запущен; агент занимается диагностикой (логи, точечные файлы, воспроизведение).
- [ ] Нет план-файла, нет Sonnet-планировщика, нет Opus-execution.
- [ ] Агент не начинает «чинить фичей»: найденную причину сначала докладывает; если фикс нетривиальный — предлагает (а не запускает молча) конвейер отдельным шагом.
- [ ] Диагностика опирается на карту/логи, а не на сплошное чтение проекта.
- FAIL, если: развёрнут конвейер планирования; агент переписал функциональность без диагноза; отчёт содержит выдуманную причину без проверки.

## TC-5 — Фича в проекте без ARCHITECTURE.md → сначала карта

**Подготовка:** выбрать (или создать в scratchpad/тестовой папке) код-проект без `ARCHITECTURE.md` — например, скопировать маленький проект в `evals/sandbox/` или использовать реальный проект, где карты ещё нет.

**Промпт:**
```
Добавь в проект <проект без ARCHITECTURE.md> фичу <любая нетривиальная фича>. Model pipeline.
```

**Ожидание:** по Стадии 2 п.2 — нет `ARCHITECTURE.md` → сначала сгенерировать его Sonnet-субагентом по контракту (Module map, Data flows, Key decisions, Conventions, футер `Generated: YYYY-MM-DD`), и только потом архитектура/execution.

**Pass/fail:**
- [ ] PASS-обязательно: агент замечает отсутствие `ARCHITECTURE.md` и **не подменяет карту сплошным чтением кодовой базы главной моделью**.
- [ ] Карту генерирует Sonnet-субагент (или агент явно запрашивает у Антона существующую карту), главная сессия — нет.
- [ ] Сгенерированный `ARCHITECTURE.md` содержит все 5 секций контракта, включая футер `Generated: YYYY-MM-DD`.
- [ ] Только после карты — план/архитектура фичи (порядок стадий соблюдён).
- [ ] Главная сессия по-прежнему читает только карту + план, точечные файлы — лишь по указанию карты.
- FAIL, если: главная модель «разобралась в проекте» чтением файлов подряд; конвейер пошёл в execution без карты; карта создана, но без обязательных секций.

## Как прогонять benchmark

1. **Когда:** после смены главной модели или моделей субагентов (sonnet/opus mapping), и после изменений `SKILL.md` (триггеры, стадии, token discipline).
2. **Как:** каждый кейс — свежая сессия с промптом из кейса, без наводящих подсказок. TC-1/TC-2/TC-4 — быстрые (роутинг виден за минуту); TC-3/TC-5 можно останавливать после стадии планирования/карты.
3. **Оценка:** PASS только при всех пунктах чеклиста; пункты «PASS-обязательно» — критические. Главный сигнал деградации: конвейер разворачивается на тривиальных/review-интентах или главная модель начинает читать кодовую базу и писать код.
4. **Фиксация:** результаты — в `evals/runs.md` (дата, модель, кейс, pass/fail, заметка). В заметке для TC-3/TC-5 указать путь созданного план-файла/карты.
5. **Уборка:** eval-план-файлы и тестовые `ARCHITECTURE.md` перенести в `archive/` или удалить по подтверждению Антона; боевые планы проектов не трогать.
