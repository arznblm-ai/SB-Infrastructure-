# Gif Ref — видео-реф в презентацию

Появился 2026-08-11 из работы над декой «Каталог AI-продуктов» (UGC Media AI-хаб): пайплайн прогнан 6 раз, здесь зафиксирован рабочий вариант.

## Вход

1. **Ссылка на видео** (YouTube Shorts / обычный YouTube / TikTok / Instagram) или путь к локальному файлу.
2. **К какому формату/слайду относится** — подпись рефа. Если Антон не сказал — спросить одним вопросом, не угадывать.
3. **Дека** — по умолчанию `tasks/UGC Media AI-хаб/deck/` (index.html + styles.css). Другая дека — только если Антон указал.

## Разделение ролей (по правилам vault)

Главная сессия: принять вход, сформировать спецификацию, визуальное ревью по скриншоту, отчёт Антону.
**Скачивание, ffmpeg, правка HTML/CSS и пересборка standalone — исполнитель** (реестр и выбор — `system/skills/route/SKILL.md`; по умолчанию Opus-субагент). Исполнителю писать только в каталог задачи, scratch и файл выдачи в `Vibecode OUT/`.

## Пайплайн (спецификация для исполнителя)

### 1. Скачать
- `python3 -m yt_dlp` (стоит у Антона), формат mp4 высотой ≤720.
- Исходник — ТОЛЬКО в scratch-каталог сессии. В vault сырые видео не кладутся.
- Локальный файл Антона (Downloads и т.п.) — не перемещать и не удалять, только читать.

### 2. Нарезать гиф-петлю
ffmpeg: `/Users/anton/Library/Python/3.11/lib/python/site-packages/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v7.1` (статический бинарь imageio-ffmpeg; в PATH ffmpeg на маке НЕТ, brew нет).

Параметры петли (стандарт деки):
- ~8 сек репрезентативного фрагмента. Сначала посмотреть контактный лист кадров и выбрать кусок, показывающий суть формата; пропускать заставки, чужие аутро-логотипы, чёрные склейки.
- `blackdetect` — найти чёрные провалы; если непрерывных 8 сек без провала нет, склеить два отрезка одним проходом кодирования.
- `cropdetect` — у шортсов бывают вшитые чёрные поля, обрезать.
- Без звука `-an`; высота 640, ширина по пропорции (чётная); `-crf 26 -preset veryslow`; `-movflags +faststart`; `-pix_fmt yuv420p`. Цель ≤1,5 МБ, обычно выходит 0,1–1 МБ.
- Имя файла — слаг формата: `deck/assets/video/<format-slug>.mp4`.

### 3. Вставить слайд-реф
В деке есть готовый шаблон `.ref-layout` (+ `.ref-layout-wide` для клипов шире 9:16):
- слева: кикер `[Реф — группа X]`, h2 с названием формата, лид 1–2 строки по смыслу карточки формата (ничего не выдумывать);
- справа: `<figure class="ref-media">` с `<video autoplay loop muted playsinline>` на высоту контентной зоны, подпись `[Реф: …]`;
- тема слайда = тема слайда группы (A/B светлые, C тёмная);
- позиция: сразу после слайда своей группы, в порядке карточек группы;
- перенумеровать `data-slide`, номера `[0N]`, хромку последующих слайдов и статический фолбэк `navTotal`; счётчик и хеши JS пересчитывает сам;
- автоплей видео активного слайда обрабатывает существующий `playSlideVideos()` — не дублировать.

### 4. Пересобрать standalone и выложить
- `build_standalone.py` (scratch; если пропал — переписать: styles.css → <style>, шрифты `assets/fonts/*.ttf` → data:font/ttf;base64, фото/видео → data URI; в конце assert, что `./assets` и `./styles` в выходном файле не осталось).
- Выход: `tasks/UGC Media AI-хаб/Каталог AI-продуктов.html` + копия поверх `/Users/anton/Desktop/Vibecode OUT/Каталог AI-продуктов.html` (правило Vibecode OUT — постоянное).
- Доложить размер файла. Ориентир: base64 даёт +33% к весу видео; файл держать в единицах МБ.

### 5. Проверка (исполнитель) + ревью (главная сессия)
- Исполнитель: локальный `python3 -m http.server` в `deck/`, скриншоты нового слайда и соседних, автоаудит (число слайдов, номера по порядку, overflow 0), в standalone видео играют (`readyState`), серверы остановить.
- Главная сессия: свой скриншот нового слайда через Browser pane; при перезаливке клипа с тем же именем — reload с cache-bust (`?v=N`), браузер агрессивно кеширует mp4.
- Отчёт Антону: что за реф, куда встал, размер файла, замеченные риски (чужие бренды/вотермарки/субтитры в кадре — назвать вслух).
