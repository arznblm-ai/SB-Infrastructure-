# Launch Workflow

### [[2026-04-03]]

Этот файл задает новый чистый цикл запуска `Portal Designer`, `Generator`, `Critic` и `presentation-art-director`.

## Принцип

Каждый раунд начинается с нуля.

Нельзя:

- молча наследовать прошлую версию deck
- ссылаться на старые замечания по памяти
- считать активной ту версию, с которой работали в прошлый раз

Нужно:

- каждый раз явно указывать активные файлы
- каждый раз явно указывать активный бриф
- каждый раз явно передавать комментарии пользователя
- каждый раз запускать review только на текущую активную версию

## Обязательный вход

Перед запуском любого агента должны быть явно определены:

- активная версия deck
- активный brief
- комментарии пользователя для этого раунда
- источник правды, если нужен fidelity pass

Если брифа нет, сначала используй [brief-template.md](../../references/brief-template.md).

## Router

Полное дерево выбора лежит в [router.md](../../references/router.md).

Коротко:

- визуальный редизайн и композиция → `portal-designer`
- содержательные, structural и production-правки → `Generator`
- финальная проверка сходства и визуального QA → `presentation-art-director`

## Порядок работы

1. Определи активную версию deck для этого раунда.
2. Определи активный brief для этого же раунда.
3. Через [router.md](../../references/router.md) выбери основного исполнителя.
4. Если нужен визуальный редизайн, сначала подставь active deck и brief в `Portal Designer`.
5. Если нужны содержательные или structural-правки, подставь тот же active deck и brief в `Generator`.
6. После изменений передай эту же активную версию и этот же brief в `Critic`.
7. Если `Critic` вернул `FAIL`, запусти новый раунд снова на той версии, которую считаешь активной после правок.
8. Если `Critic` вернул `PASS` и важна близость к approved source, запусти `presentation-art-director` как финальный визуальный gate.
9. После этого отдавай deck человеку на финальное утверждение.

## Retry loop

- `Critic` работает максимум `3` раунда на одну задачу, если пользователь не просит продолжать дальше.
- Если после `3` раундов всё ещё `FAIL`, координатор должен остановить цикл и явно сформулировать, что именно не может пройти.

## Правила оркестрации

- `Portal Designer` используется, когда пользователь хочет именно редизайн, усиление композиции, ритма и визуального языка внутри Portal design code, без Portal logo по умолчанию
- `Generator` используется для смысловых, структурных и production-правок
- `Critic` всегда read-only
- `presentation-art-director` используется как финальный визуальный QA, если важны сходство, типографика и layout fidelity
- если нет brief, раунд не должен стартовать
- если пользователь меняет направление, старое направление не считается обязательным
- если пользователь хочет начать заново, активная версия выбирается заново, без ссылок на прошлые итерации
