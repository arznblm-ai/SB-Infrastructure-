# Transcript Summarizer — обработка сырья в structured knowledge

> **Thesis:** Skill забирает source materials из `transcripts/`, классифицирует каждый как лекцию или встречу по паттернам речи, создаёт structured summary по documentation framework, и сохраняет в `education/` или `meetings/`.

---

## Принцип работы

Транскрипт — это сырьё. Summary — это контекст. Агенты работают с контекстом, не с сырьём. Этот skill превращает первое во второе.

```
transcripts/ (сырьё)
    ↓ classify
    ├── education/ (summary лекций)
    └── meetings/ (summary встреч)
```

---

## Протокол обработки

### Шаг 1: Сканирование transcripts/

Прочитай все файлы в `/Users/anton/AI AGENT FOLDER/Second Brain/transcripts/`.

Для каждого файла проверь: **существует ли уже summary?**

Не сканируй `sessions/`: Claude-сессии живут отдельно и не входят в этот workflow.

Как проверить:
- Для файла `{course} {transcript} ТЕМА – ДАТА.md` → ищи `{course} {summary} ТЕМА – ДАТА.md` в `education/`
- Для файла `{meeting} {transcript} ТЕМА – ДАТА.md` → ищи `{meeting} {summary} ТЕМА – ДАТА.md` в `meetings/`
- Если встретился legacy source file без `{transcript}`, не переименовывай автоматически; используй как источник, но считай исключением
- Совпадение по дате + похожей теме (не обязательно точное совпадение имени)

Если summary уже есть — пропускай. Выведи список необработанных файлов и спроси пользователя: обработать все или выбрать конкретные.

### Шаг 2: Оценка длины и классификация

#### 2a. Сначала определи длину файла

Выполни: `wc -l "ПУТЬ_К_ФАЙЛУ"`

- **< 300 строк** — читай целиком за один раз
- **300–800 строк** — читай двумя блоками: начало (0–400) и конец (400–конец)
- **> 800 строк** — читай тремя блоками: начало (0–300), середина (середина±150), конец (последние 300 строк)

**Цель:** составить картину всего транскрипта, не только начала.

#### 2b. Классифицируй по трём типам

После чтения блоков определи тип:

##### → Conference / Panel (конференция, панельная дискуссия)

Признаки:
- **3+ различных спикера**, каждый с отдельным блоком выступления
- **Ведущий** переключает между спикерами: "следующий спикер", "давай тебе слово", "спасибо, теперь..."
- **Каждый спикер независим** — свои слайды, демо, тема
- **Источник:** Krisp/Zoom конференций, VibeconF, публичные ивенты

→ **Сохранять в `education/`** с prefix `{course}`
→ **Структура summary: отдельный раздел на каждого спикера**

##### → Education (лекция, воркшоп, курс)

Признаки:
- **Один доминирующий спикер** (>70% текста) на протяжении ВСЕГО транскрипта
- **Длинные непрерывные блоки** речи (>10 строк подряд от одного спикера)
- **Обучающий тон:** объясняет концепции, показывает примеры, даёт задания
- **Маркеры:** "давайте разберём", "как это работает", "важно понимать", "шаг 1, шаг 2", "домашнее задание", "prework", "workshop"
- **Источник:** Whisper-транскрипция видео, AI Mindset лекции

→ **Сохранять в `education/`**

##### → Meeting (встреча, обсуждение, 1-on-1)

Признаки:
- **2–3 активных спикера** с существенным временем у каждого
- **Короткие реплики:** вопрос-ответ, обсуждение, перебивание
- **Деловой тон:** обсуждение проектов, задач, дедлайнов, бюджетов
- **Маркеры:** "а что думаешь?", "давай так сделаем", "сколько стоит", "дедлайн", "клиент", "проект"
- **Action items:** конкретные договорённости, кто что делает
- **Источник:** Krisp-транскрипция звонков, Zoom-записи рабочих встреч

→ **Сохранять в `meetings/`**

##### → Неопределённость

Если классификация неочевидна, спроси пользователя. Предложи свою гипотезу с обоснованием.

> ⚠️ **Частая ловушка:** Конференция в начале выглядит как один спикер — ведущий открывает или первый докладчик долго говорит. Если видишь фразы "следующий спикер", "зову [имя]", "тебе слово" — это конференция, читай дальше до конца.

### Шаг 3: Полное чтение и создание summary

Перед написанием summary прочитай documentation framework:
`/Users/anton/AI AGENT FOLDER/Second Brain/system/rules/{POS} {rule} documentation framework – 2026-04-04.md`

**Прочитай транскрипт полностью**, используя стратегию из Шага 2a. Для файлов > 800 строк:
1. Читай блоками по 400–500 строк с нахлёстом
2. После каждого блока фиксируй: спикер(ы), ключевые темы, важные факты/цифры
3. Перед написанием summary убедись: последний прочитанный номер строки = общая длина файла

**Если файл длиннее 1500 строк** — это скорее всего конференция с несколькими спикерами. Ожидай пропорционально большой summary (1 раздел = 1 спикер).

### Шаг 4: Именование и сохранение

| Тип | Папка | Формат имени |
|-----|-------|-------------|
| Education | `education/` | `{course} {summary} [тема] – YYYY-MM-DD.md` |
| Meeting | `meetings/` | `{meeting} {summary} [тема] – YYYY-MM-DD.md` |

**Правила именования:**
- Тема в summary может отличаться от темы в транскрипте (бери более точную)
- Дата — из транскрипта (не текущая дата)
- EN DASH `–` перед датой
- Максимум 80 символов в имени файла

## Режимы работы

### Режим: Batch (обработать всё)
Триггер: "обработай транскрипты", "разложи сырьё", "batch summary"
Действие: все 5 шагов для всех необработанных файлов.

### Режим: Single (один файл)
Триггер: "обработай [имя файла]", "сделай summary для [тема]"
Действие: шаги 2-4 для конкретного файла.

### Режим: Scan (только проверка)
Триггер: "что нового в transcripts", "какие транскрипты не обработаны"
Действие: только шаг 1, вывести список необработанных.

## Качество summary

Хороший summary:
- **Thesis** позволяет понять суть, не читая дальше
- **Structure** содержит все ключевые концепции/решения с объяснениями
- **Process** описывает workflow и практические рекомендации
- **Ground Truth** связывает с оригиналом
- Длина: 80-200 строк (не длиннее оригинала, но достаточно для полноты)
- Цитаты спикера — только самые яркие и ёмкие (1-3 штуки)

Плохой summary:
- Простой пересказ в хронологическом порядке
- Копирование кусков транскрипта без обработки
- Потеря ключевых концепций и практических советов
- Отсутствие structure/process разделения
