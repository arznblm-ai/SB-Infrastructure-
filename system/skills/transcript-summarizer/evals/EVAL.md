## ⚠️ Режим прогона: DRY-RUN ONLY

Все кейсы обрабатываются **в dry-run режиме**:

- Результат (summary) **НЕ сохранять** в реальные `meetings/` или `education/`.
- Вывод — либо целиком в чат, либо в файл внутри `evals/output/` (папку создать при первом прогоне: `system/skills/transcript-summarizer/evals/output/`).
- Фикстуры **не перемещать** и **не переименовывать**; `transcripts/` не трогать вообще.
- В промпте запуска каждый раз явно указывать dry-run (см. команды ниже).

## Тест-кейсы

### TC-1 — Встреча (fixture-meeting.md)

**Промпт запуска:**
```
Прочитай SKILL.md скилла transcript-summarizer и обработай по нему файл
"system/skills/transcript-summarizer/evals/fixture-meeting.md".
DRY-RUN: summary не сохраняй в meetings/ — покажи в чате (или запиши в evals/output/)
и отдельно назови: (а) классификацию, (б) целевую папку, (в) имя файла, которое ты бы дал.
```

**Ожидаемый роутинг:** классификация `meeting`, целевая папка `meetings/`.

**Чеклист pass/fail:**
- [ ] Классификация: `meeting` (2 спикера, короткие реплики, деловой тон, договорённости).
- [ ] Целевая папка: `meetings/` (названа, но файл туда НЕ записан).
- [ ] Имя файла: формат `{meeting} {summary} [тема] – 2026-05-14.md`, EN DASH `–` перед датой (не дефис), ≤ 80 символов; дата — из транскрипта (2026-05-14), не текущая.
- [ ] Структура summary по шаблону Meeting из SKILL.md: frontmatter (tags, date, status, source, participants), заголовок, `> **Thesis:**`, `**Overview:**`, `## 1.0 Structure`, `## 2.0 Process`, `## 3.0 Action Items`, `## 4.0 Ground Truth`.
- [ ] Thesis first: thesis стоит до содержательных секций и передаёт главный результат встречи одним предложением.
- [ ] Action items только из транскрипта, ничего выдуманного. Эталон (все должны быть покрыты, лишних — ноль):
  - Ольга — допсоглашение на калькулятор (~60 тыс.) — сегодня
  - Ольга — запросить цифры у маркетолога клиента — ответ до пятницы
  - Ольга — задача дизайнеру на перекраску по новому брендбуку
  - Ольга — статус по цифрам Марату в пятницу
  - Ольга/разработчик — инструкция по деплою до сдачи
  - Марат — письмо Сергею с допсоглашением и планами А/Б — сегодня вечером
- [ ] Ключевые решения не потеряны: кнопка-якорь вместо калькулятора на первом экране, блок цифр вместо отзывов, дедлайн 26 мая не двигается, план А/Б, хостинг на стороне клиента.

## Как прогонять benchmark

1. **Когда:** после смены модели (главной или субагентской) и после любого существенного изменения `SKILL.md` (классификация, шаблоны, роутинг).
2. **Как:** в свежей сессии прогнать TC-1 … TC-5 по промптам выше, строго в dry-run. Каждый кейс — отдельной командой, без подсказок сверх промпта запуска.
3. **Оценка:** кейс PASS, только если выполнены **все** пункты его чеклиста. Любой провал пункта → FAIL с заметкой, какой пункт упал.
4. **Фиксация:** результаты записать в таблицу `evals/runs.md` (дата, модель, кейс, pass/fail, заметка). Одна строка на кейс на прогон.
5. **Деградация:** если кейс, который раньше был PASS, стал FAIL — это регрессия; сначала проверить, не изменился ли SKILL.md/фикстура, затем фиксировать как model regression.
6. **Уборка:** после прогона содержимое `evals/output/` можно чистить; фикстуры и EVAL.md не трогать.
