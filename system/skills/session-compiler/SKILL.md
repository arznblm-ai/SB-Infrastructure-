# Session Compiler — из сырых сессий в связанные знания

> **Thesis:** Skill читает новые транскрипты в `sessions/` (raw-слой), выжимает из них дневной лог и долговечные знания, и раскладывает в `sessions/compiled/` (derived-слой): `daily/` + `topics/` + журнал `log.md`. Паттерн: Karpathy LLM-wiki (raw → compiled) + claude-memory-compiler.

## Зачем

`sessions/` — архив: 200+ сырых транскриптов, которые никто не перечитывает. Компиляция превращает их в: (а) быстрый ответ «что делалось и почему», (б) переиспользуемые решения и паттерны, привязанные к темам, а не к датам.

## Слои

| Слой | Путь | Правило |
|---|---|---|
| Raw (не трогать) | `sessions/claude/exports/**/*.md`, `sessions/codex/exports/**/*.md`; legacy-архив `sessions/*.md` (до 2026-07-06, новых не появляется) | Только чтение. Auto-import, владелец — Claude to obsidian |
| Daily log | `sessions/compiled/daily/{self} {summary} sessions daily log – YYYY-MM-DD.md` | Один файл на день, в котором были сессии |
| Topic-статьи | `sessions/compiled/topics/{self} {analysis} <тема> – YYYY-MM-DD.md` | Живые документы; дата в имени = дата создания, актуальность — в frontmatter `updated:` |
| Журнал | `sessions/compiled/log.md` | Append-only: что и когда компилятор изменил (аудит-трейл + state последнего прогона) |

## Workflow

1. **Определи окно.** Прочитай последнюю запись `sessions/compiled/log.md` → компилируй сессии с датой позже последнего прогона. Если журнал пуст — возьми последние 7 дней (или окно, названное Антоном).
2. **Собери новые сессии.** `ls` по `sessions/claude/exports/YYYY/MM/` и `sessions/codex/exports/YYYY/MM/` (плоский `sessions/` — legacy-архив до 2026-07-06, для старых окон), отфильтруй по дате из имени/frontmatter. Крупные транскрипты читай выборочно: заголовок, [user]-реплики и финальные ответы важнее промежуточных tool-call строк.
   Правила подсчёта (из опыта первого прогона 2026-07-06):
   - **Единица — сессия, не файл.** Report-артефакты рядом с транскриптом (`{automation} {report} …` той же даты/задачи) — часть той же сессии.
   - **Дубликаты `session_id`** (Codex-экспортёр иногда пишет partial + complete): бери файл с бóльшим числом сообщений, partial игнорируй.
   - **Служебные сессии** (ежедневные export-прогоны и т.п. без решений/уроков): в daily log — одной строкой с пометкой «без новых знаний» или пропускай целиком; topic-статьи из них не делать (кроме повторяющихся операционных граблей).
   - **Критерий расширения окна** — не количество raw-файлов, а количество дней с СОДЕРЖАТЕЛЬНЫМИ сессиями: если таких дней < 2, расширь окно до 14 дней и отметь это в log.md.
3. **Дневной лог.** Для каждой даты с сессиями создай/обнови файл в `daily/`:
   - какие сессии были (ссылки на raw-файлы), над чем работа;
   - принятые решения и их причины;
   - созданные/изменённые артефакты (пути);
   - уроки и грабли (что не сработало);
   - открытые хвосты.
4. **Topic-статьи.** Извлеки долговечное (решение, паттерн, конфигурация, договорённость по проекту) и вплети в статью по теме в `topics/` (создай, если темы нет; ищи существующую через `topics/` listing и Vault Semantic Search, чтобы не плодить дубликаты):
   - каждый факт — со ссылкой на сессию-источник и датой;
   - устаревший факт НЕ удаляй — помечай `~~факт~~ (superseded 2026-MM-DD: <новый факт>)`;
   - связывай статьи между собой и с проектами wiki-links `[[...]]`.
5. **Журнал.** Допиши в `log.md` одну запись: дата прогона, окно, сколько сессий обработано, какие файлы created/updated.
6. **Отчитайся** в чат: 3-5 строк — что скомпилировано, самые важные извлечённые знания.

## Frontmatter derived-файлов

```yaml
---
tags:
  - type/summary   # или type/analysis для topics
  - project/self
  - source/session-compiler
date: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "[[имя raw-сессии]]"
---
```

## Verification

- Каждый created/updated файл существует и непуст; frontmatter валиден.
- Каждый факт в topic-статье имеет источник (имя сессии). Нет фактов без источника.
- Raw-файлы в `sessions/` не изменены (только чтение).
- Запись в `log.md` добавлена, прежние записи не тронуты.

## Границы и gates

- Пишет ТОЛЬКО в `sessions/compiled/`. Обновления `context/` — не его работа: если из сессий вылезли факты о жизни/бизнесе Антона, сформулируй handoff-заметку для Personal Context Updater в отчёте, не пиши в context/ сам.
- Секреты/токены, случайно попавшие в транскрипты, в compiled-слой не переносить.
- Ночная автоматизация этого скилла требует явного решения Антона (стоимость); по умолчанию — ручной/по запросу прогон.
